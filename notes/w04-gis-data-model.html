Spatial data/ Geodata

Geospatial data is traditionally divided into two great classes, raster and vector.

Traditionally, systems have tended to specialize in one or other of these classes; therefore, translation between them (rasterization for vector-to-raster and vectorization for raster-to-vector has been a thorny problem.

Raster

raster data is structured as an array or grid of cells, referred to as pixels (picture elements). Each cell in a raster is addressed by its position in the array (row and column number). A point may be represented by a single cell, an arc by a sequence of neighboring cells and a connected area by a collection of contiguous cells. Pixel value stands for the value of the pixel.

  • There are two types of raster data: continuous (e.g., elevation measurements) and discrete (e.g., thematic data, raster land use data).

Vector

a vector is a finite straight-line segment defined by its end-points.

  • A point is just given as a coordinate.
  • An arc is discretized as an sequence of straight-line segments;
  • An area is defined in terms of its boundary, represented as a collection of vectors.

The vector data representation is inherently more efficient in its use of computer storage than raster, because only points of interest need be stored.

A disadvantage is that vectors assume a hard-edged boundary model of the world that does not always accord with our observations.

Shapefile

An ESRI Shapefile is a binary format, not a text format.

Each layer can contain only one geometry type, such as points, polylines or polygons.

OpenStreetMap (OSM)

OpenStreetMap is a website that uses an open geographic database which is updated and maintained by a community of volunteers via open collaboration.

OSM was founded in 2004. It is so called volunteered geographic information, VGI.

A map feature or element is modelled as one of three geometric primitives: node, way, and relation (optional). 點、線

Attributes are represented by key: value pairs.

Sequent edits (collaborative editing) are recorded.

WMS: image; WFS: vector; WMTS:…

Support services (XML-based Open standards)

  • OGC Web Map Service (WMS)
    • The WMS service returns geo-registered map images (JPEG, PNG, etc.) from one or more distributed geospatial databases (announced in 2006).
  • OGC Web Feature Service (WFS)
    • The WFS service standard returns geographical features like points, lines and polygons in a geographical file format (announced in 2005).
  • OGC Web Map Tile Service (WMTS)
    • The WMTS standard complements the existing Web Map Service standard of the OGC. For heavy use and high scalability, the OGC has developed the WMTS service standard. It is an area-wide collection of consistently addressable, seamless map image tiles organized in a pyramid with fixed scales. Clients request as many tiles as needed to cover the requested area (announced in 2010).

XYZ → Google Maps & OSM

  • Google Maps and OpenStreetMap follows this specification. URL is composed of XYZ, such as http://.../Z/X/Y.png. Z is the zoom level, X and Y are the number of tiles.
    • Google road map: http://mt0.google.com/vt/lyrs=m&hl=en&x={x}&y={y}&z={z}
    • OSM: http://tile.openstreetmap.org/{z}/{x}/{y}.png

TMS (Tile Map Service) → 較少使用

  • Tile Map Service is a specification for tiled web maps, developed by the Open Source Geospatial Foundation (OSGeo).
  • The only difference between XYZ and TMS is that the y-axis is flipped. (XY相反)
