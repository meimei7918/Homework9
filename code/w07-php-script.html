這包範例在做什麼

老師配合 W07 PHP 講義的 22 支小程式和 2 個資料檔，幾乎每張投影片都有對應的檔案：變數範圍、var_dump、運算子、陣列、輸出、printf、foreach、字串函式、時間、JSON、header、檔案讀寫與上傳。另外附了一支 JavaScript 版的變數範圍範例 php1_jsvScope.html，可以和 PHP 對照。

建議閱讀順序就是下方檔案列表的順序（大致依講義順序排）。

GitHub Pages 無法執行 PHP，所以 .php 檔只能看原始碼。下面的「重點解說」附了我們用 PHP 8.3 實際執行的輸出（課程用 8.5，這些範例的結果相同）。想自己跑，可以用 phptest 的 Docker 環境，或把程式貼到資源列表裡的線上 PHP 執行網站。

講義中還提到 function.php、php1_include.php、ajax1.html、ajax2.html、ajax001.php、ajax002.php、php1_proxy.php、getdatafp.html，這幾個檔案不在這次的壓縮檔裡，內容請看講義筆記。

範例檔案

重點解說

php1_v.php 與 php1_jsvScope.html：兩種語言的變數範圍

PHP 的函式裡預設看不到外面的全域變數。實際執行 php1_v.php，函式裡讀 $a 會出現 Warning: Undefined variable $a；用 global 宣告的 $c、$d 和用 $GLOBALS['f'] 讀的都正常。static 的 $e 第一次呼叫是 600，第二次是 700：

======== inside function=========
Warning: Undefined variable $a
Variable a inside function is:
Variable b inside function is: 200
Variable c inside function is: 300
Variable d inside function is: 400
Variable e inside function is: 600     ← 第二次呼叫變成 700
Variable f inside function is: 600

JavaScript 剛好相反，函式裡可以直接讀全域變數。php1_jsvScope.html 可以在網站上執行，打開 Console 會看到：函式內四個變數都印得出來，但函式外讀 z 時出現 ReferenceError: z is not defined，程式就此中斷，後面的 m 和第二次 tFun() 都沒有執行。把那一行註解掉再跑，就能看到 m 這個沒宣告的變數在函式外也讀得到 400。

php1_vdump.php、php1_operators.php：輸出看起來怪怪的

echo "Data type of variable b:" . var_dump($b) 的實際輸出是先出現 float(200)，下一行才是 Data type of variable b:。PHP 要先把整串字算完才 echo，而 var_dump 在計算過程中就已經直接印出來了，它本身回傳 null。

php1_operators.php 的輸出是 2、2、1、12522、mn。12522 不是一個數字，而是 5**3 的 125 後面沒換行，緊接著 $i .= $j . "<br />" 的結果 22。.= 的優先順序比 . 低，所以先算右邊。

php1_array.php：在 PHP 8 會停在最後兩行

老師用 /* … /**/ 的技巧開關一段程式：刪掉開頭的 /*，結尾的 /**/ 就變成空註解，整段恢復執行。目前 $carinfo 那段是關著的，所以最後的 count($carinfo) 拿到 null。舊版 PHP 只會出警告，PHP 8 會變成致命錯誤：

age:3
people:4
Warning: Undefined variable $carinfo
Fatal error: Uncaught TypeError: count(): Argument #1 ($value) must be of type Countable|array, null given

把 $carinfo 那段開頭的 /* 刪掉就能正常執行。

shelter.json 有 194 筆收容所，跑完得到 36 個不重複的聯絡人姓名。檔案開頭有 BOM，第一個欄位名稱前多了一個看不見的字元；這裡比對的是第四個欄位，所以不受影響，但如果要用第一個欄位「災民收容所編號」比對，就會對不到。

php1_file.php：Big5 的 CSV

WaterQ.csv 是 Big5 編碼，直接輸出在 UTF-8 的網頁或終端機上是亂碼（網站的原始碼檢視已經自動用 Big5 解碼）。老師準備了 mb_convert_encoding(…, "UTF-8", "big5") 那行但註解掉了。實際測試發現資料裡的全形斜線「未／稍受污染」用 "big5" 會變成問號，改用 "CP950"（Windows 的 Big5）才完全正確。另外，檔案不存在時的分支印的是 File exists!!，訊息寫反了。

為了在網站上執行所做的修改

無，這包範例沒有修改任何檔案。壓縮檔原本的最外層資料夾 script/ 拿掉了，裡面的結構不變。
