這包範例在做什麼

老師用來建立課程 PHP 環境的設定：一個 Dockerfile 以官方 php:8.5-cli 映像檔為基礎，把 src/ 的程式和 custom.ini 設定複製進容器，再用 PHP 內建的開發用伺服器提供網頁。src/ 裡只有兩支測試程式：一支看網頁輸出，一支在命令列執行。

建議閱讀順序：Dockerfile → custom.ini → src/first.php → src/showtime.php。

GitHub Pages 只能放靜態檔案，沒辦法執行 PHP，所以這頁只能看原始碼。要跑起來，請在自己的電腦安裝 Docker，下載整包後照下面的指令做。

範例檔案

重點解說

Dockerfile：從建立映像檔到開網頁

FROM php:8.5-cli
WORKDIR /app
COPY src/ /app
COPY custom.ini /usr/local/etc/php/conf.d/
EXPOSE 80
CMD ["php", "-S", "0.0.0.0:80"]

在這個資料夾裡執行：

docker build -t phptest .                                   # 依 Dockerfile 建立映像檔
docker run --rm -p 20080:80 phptest                         # 啟動伺服器，瀏覽器開 http://localhost:20080/first.php
docker run -it --rm --name example -p 20080:80 phptest bash # 或進入容器的命令列
php -v                                                      # （在容器裡）查看版本
php -q showtime.php                                         # （在容器裡）執行命令列程式

-p 20080:80 把主機的 20080 埠接到容器的 80 埠；EXPOSE 只是標示用途，沒有這個 -p 主機就連不到。COPY 是建立映像檔當下複製進去，之後修改 src/ 要重新 docker build。想邊改邊看，可以改用 -v "$(pwd)/src:/app" 把資料夾直接掛進容器。

custom.ini：短標籤與錯誤顯示

short_open_tag=On 允許開頭標籤省略 php 三個字。src/first.php 的第一段就是短標籤；如果沒有這個設定，那段不會被執行，會原封不動送到瀏覽器。display_errors=On 讓錯誤直接顯示在畫面上，開發時方便，正式網站要關掉。

src/first.php 與 src/showtime.php

first.php 先輸出 The first PHP script!，接著 phpinfo() 印出一整頁 PHP 設定，可以在裡面找 short_open_tag 確認 custom.ini 有沒有生效。showtime.php 是 while(1) 無窮迴圈，每秒印一次時間，要按 Ctrl＋C 停止；用瀏覽器開它，頁面會一直載入不完。

為了在網站上執行所做的修改

無，這包範例沒有修改任何檔案。壓縮檔原本的最外層資料夾 image/ 拿掉了，裡面的結構不變。

動手改改看

  • 把 W07 script 包的 php1_time.php 放進 src/，重新 build 後用瀏覽器開，確認時間是臺灣時間
  • 把 custom.ini 的 short_open_tag 改成 Off，重新 build，看看 first.php 的畫面有什麼變化
