學習目標

  • 能說出 VS Code、Git、Docker 各自負責什麼
  • 能在自己的電腦（macOS 或 Windows）裝好三個工具並確認版本
  • 能用 docker build 與 docker run 把範例專案跑起來

三個工具的分工

工具是什麼在這門課的用途
Visual Studio Code程式碼編輯器寫 HTML、CSS、JavaScript、PHP
Git版本控制系統version control記錄每次修改、和組員協作、從遠端取得範例專案
Docker用容器container建置、執行與管理應用程式的平台不用在電腦上裝 PHP，就能跑起有 PHP 的網站

工作方式是：在 VS Code 裡改程式碼 → 用 Git 管理版本 → 用 Docker 把程式放進容器執行 → 用瀏覽器看結果。

安裝步驟

VS Code

到官網下載對應作業系統的版本安裝即可。安裝後會常用到它內建的終端機（Terminal），後面的指令都在這裡打。

Git

macOS：先裝套件管理工具 Homebrew（到 brew.sh 複製第一行指令貼進終端機、輸入密碼），確認 brew --version 有版本號後，再執行 brew install git，最後用 git --version 確認。

Windows：到 git-scm.com 下載 Windows x64 安裝檔安裝。

兩個系統裝好後都要設定使用者名稱與 email，Git 會把它記在每一次提交上：

git config --global user.name "你的名字"
git config --global user.email "你的 email"
git config --list   # 檢查設定

Docker

macOS：到 Docker 官網下載 Docker Desktop（Apple 晶片選 Apple Silicon 版），打開後可以跳過登入，確認 Docker 有在執行。

Windows：要先裝 WSLWindows Subsystem for Linux，重新開機，再裝 Docker Desktop（AMD64 版）。安裝時勾選使用 WSL 2，裝完到 Settings → General 確認「WSL 2 based engine」有勾。

Windows 沒先裝 WSL 就裝 Docker，通常會啟動失敗。順序是：WSL → 重開機 → Docker Desktop。

第一個專案：四個步驟

  1. 用 git clone 取得老師的範例專案
  2. 用 docker build 建立 映像檔image
  3. 用 docker run 把映像檔跑成容器
  4. 修改程式後，重複第 2、3 步

範例專案的結構：專案資料夾裡有一個 image/，放所有程式碼和 Dockerfile（環境需求）；程式碼在 image/src/，樣式在 src/css/。

Dockerfile 在說什麼

老師的 Dockerfile 做的事情可以用白話說：以官方的 PHP 8.2 命令列版本為基礎，在容器裡建立 /app 資料夾，把 src/ 的內容複製進去，開放 80 port，容器啟動時執行 PHP 內建的網頁伺服器。

build 與 run 的參數

docker build -t example image/
docker run -i --rm --name example -p 21822:80 example
參數意思
-t example幫映像檔取名（tag）為 example；一個映像檔可以有多個 tag
image/Dockerfile 所在的資料夾路徑
-i互動模式
--rm容器停止後自動刪除
--name example容器名稱
-p 21822:80把電腦的 21822 port 對應到容器的 80 port，所以瀏覽器開 http://localhost:21822
最後的 example要執行的映像檔名稱

常用 Docker 指令

對象指令作用
映像檔docker images列出映像檔
docker rmi 名稱刪除映像檔
docker build -t 名稱 路徑建立映像檔
docker pull 名稱下載映像檔
docker push 名稱上傳映像檔
容器docker run把映像檔跑成容器
docker ps -a列出容器（含已停止的）
docker rm -f 名稱刪除容器
docker exec -it 名稱 bash進入執行中的容器
docker start / stop / restart啟動、停止、重啟容器

小結

VS Code 寫程式、Git 管版本、Docker 提供一致的執行環境。映像檔是「食譜」，容器是「照食譜做出來、正在跑的那一份」。改了程式就重新 build、再 run。
