觀念測驗

點選項作答，作答後會顯示解析。

1. 想分析「樹冠層的高度」，應該用哪一種資料？

  1. DEM
  2. DSM
  3. Shapefile 的 .shx
  4. WMTS 圖磚

DSM 包含植物與建物的表面高度；DEM 是去掉這些的裸露地表。兩者相減就能得到樹或建物的高度。

2. 關於向量資料，下列何者正確？

  1. 由像素陣列組成
  2. 最適合表示連續變化的高程
  3. 只存關心的點，比網格省空間，但假設邊界是硬的
  4. 精度取決於網格大小

向量用座標表示點線面，只存需要的位置所以省空間；缺點是邊界是清楚的線，不適合漸變的現象。像素、網格大小是網格資料的特性。

3. Shapefile 中存放「屬性表」的是哪個檔？

  1. .dbf
  2. .shp
  3. .shx
  4. .geojson

.shp 是幾何、.shx 是幾何索引、.dbf 是屬性。少了 .dbf 只看得到形狀，沒有欄位資料。

4. 某份政府資料的座標是 X = 304470, Y = 2767813，最可能是哪個座標系統？

  1. EPSG:4326 WGS84
  2. EPSG:3857 Web Mercator
  3. EPSG:3826 TWD97 TM2
  4. 無法判斷

X 6 位數、Y 7 位數、單位公尺，是 TWD97（或 TWD67）TM2。政府 2000 年後的資料主要是 TWD97。Web Mercator 的 X 在臺灣是 8 位數（約 13,500,000）。

5. 哪個 OGC 服務回傳的是「點、線、面圖徵本身」而不是圖片？

  1. WMS
  2. WMTS
  3. XYZ
  4. WFS

WFS（Web Feature Service）回傳向量圖徵與屬性。WMS 回傳畫好的地圖圖片，WMTS 回傳預先切好的圖磚。XYZ 是圖磚網址規則，不是 OGC 標準。

6. 縮放層級 z = 3 時，整個世界共有幾張圖磚？

  1. 9
  2. 16
  3. 64
  4. 256

每邊 2z = 8 張，總數 8 × 8 = 64，也就是 43。

7. XYZ 和 TMS 兩種圖磚規則的差別是？

  1. y 軸方向相反
  2. x 軸方向相反
  3. TMS 的圖磚是 512 像素
  4. XYZ 不能用在 OpenLayers

兩者只差在 y 從上往下數（XYZ）或從下往上數（TMS）。換算：TMS 的 y = 2z − 1 − XYZ 的 y。

8. OpenStreetMap 的三種基本元素是？

  1. point、line、polygon
  2. node、way、relation
  3. feature、layer、map
  4. key、value、tag

OSM 用 node（點）、way（線或封閉成面）、relation（元素間的關係）。屬性則用 key=value 標籤。

實作題

1. 手算圖磚編號圖磚

台北 101 位於經度 121.5645°、緯度 25.0340°。算出它在 z = 10 時落在哪一張 XYZ 圖磚（x、y），以及對應的 TMS y 值。再用 OSM 圖磚網址打開那張圖，確認 101 在圖裡。

提示

令 n = 2z：

x = floor( (經度 + 180) / 360 × n )
y = floor( (1 − ln(tan(緯度) + 1 / cos(緯度)) / π) / 2 × n )   ← 緯度要先換成弧度

可以在瀏覽器 Console 用 Math.floor、Math.log、Math.tan、Math.cos、Math.PI 計算。

參考解答 
const lon = 121.5645, lat = 25.0340, z = 10, n = 2 ** z;   // n = 1024
const r = lat * Math.PI / 180;
const x = Math.floor((lon + 180) / 360 * n);                                      // 857
const y = Math.floor((1 - Math.log(Math.tan(r) + 1 / Math.cos(r)) / Math.PI) / 2 * n); // 438
const tmsY = n - 1 - y;                                                            // 585

XYZ：x = 857、y = 438；TMS：y = 585。圖磚網址：https://tile.openstreetmap.org/10/857/438.png，圖中可以看到臺北盆地。

2. 用 Overpass turbo 抓臺大附近的咖啡店OSM

在 Overpass turbo 把地圖移到臺大公館一帶，查詢所有 amenity=cafe 的點，匯出成 GeoJSON，並在 geojson.io 打開確認。

提示

最簡單的方法是按 Wizard，輸入 amenity=cafe。查詢語法裡的 {{bbox}} 代表目前地圖畫面的範圍。

參考解答 
[out:json][timeout:25];
(
  node["amenity"="cafe"]({{bbox}});
  way["amenity"="cafe"]({{bbox}});
);
out body;
>;
out skel qt;

按 Run 之後，Export → Data → GeoJSON 下載。有些咖啡店在 OSM 上是畫成建物輪廓（way），所以查詢同時包含 node 和 way。

3. 在 QGIS 把 TWD97 的 CSV 轉成網頁用的 GeoJSONQGIS、座標系統

把下面三行存成 places.csv，在 QGIS 以 TWD97（EPSG:3826）加入，再匯出成 EPSG:4326 的 GeoJSON。最後用文字編輯器打開，確認座標變成經緯度。

name,x,y
國立臺灣大學,304470.2,2767813.3
台北101,306965.5,2769662.2
臺北車站,302166.2,2771171.6
提示

加入 CSV 時 X field 選 x、Y field 選 y，Geometry CRS 要選 EPSG:3826，不是預設的 4326。匯出時在 Save Features As 的 CRS 改成 EPSG:4326。

參考解答
  1. Layer → Add Layer → Add Delimited Text Layer，選 places.csv；Geometry definition 選 Point coordinates，X field = x、Y field = y，Geometry CRS = EPSG:3826 - TWD97 / TM2 zone 121 → Add。三個點應該出現在臺北市區。
  2. 在圖層上按右鍵 → Export → Save Features As；Format = GeoJSON、CRS = EPSG:4326 - WGS 84 → OK。
  3. 打開輸出檔，臺大的座標應約為 [121.5397, 25.0174]（經度在前）。如果加入後點不在臺灣、或整個圖層找不到，多半是加入時把 CRS 留在預設的 EPSG:4326，QGIS 把 304470 當成「經度」而無法正確定位。
